A herdr plugin · macOS & Linux

Let them graze.Keep the fence.

fence turns a herdr space into a pen. Every shell in it can write its own folder, reach the domains you allow, and nothing else. The kernel holds the fence, and herdr tells you when something runs into it.

herdr plugin install zenodea/fence

For Claude Code, Codex, Gemini CLI, or anything else you'd run in a shell.

      Five rails, two posts, and the gaps between

      Each rail is something a pen can't do. A fence has gaps too, and fence is one more layer, not a vault, so the real ones are drawn in.

      FilesWrites land in the pen's folder, /tmp and the agents' own state. Everything else is read-only.

      What's in the pen is the agent's unless you hide it. The sealed profile hides .env files and keys; the Files tab of the pen's window hides anything else.

      Secrets~/.ssh, ~/.aws, ~/.config/gh, shell history and browser profiles can't be read at all. Tokens are dropped from the environment.

      The macOS keychain stays reachable: your agent keeps its login there. macOS still asks before handing out anything else.

      Later, outside.git/hooks, .claude/settings.json, .envrc: anything that would run code outside the pen later stays read-only.

      ~/.claude.json has to stay writable, and MCP servers live in it. A tripwire tells you the moment they change.

      NetworkOut only through fence's proxy, only to the pen's domains. Going around it fails in the kernel. This machine is never reachable.

      An allowed domain can carry data out. The proxy reads the address, not what's inside the TLS. strict keeps the list to the model APIs.

      herdr and other appsNo opening, typing into or reading other panes; only status for its own. On macOS: no Apple Events, no open, no clipboard, no signals to your other processes.

      The posts are your kernel

      Every pane in a pen runs fence shell: it starts the pen's proxy and its stand-in for herdr's socket, then runs your login shell inside the operating system's own sandbox. Your aliases and prompt come along. Whatever the agent starts inherits the fence and can't take it down.

      If the sandbox can't start, the pane says so and stays empty. It never falls back to an unfenced shell.

      How high to build it

      Every pen has a profile, from sealed to open. Switch it from the pen's window, or in the pane above to see what changes.

      sealed 13 domains · .git read-only

      strict, with the pen's own secrets hidden and its history read-only: the agent reads and diffs, you commit.

      hides **/.env* · **/*.key · credentials.json · *.tfstate …

      strict 13 domains

      The pen's folder and the agents' own state. Out to the model APIs, and nowhere else.

      api.anthropic.com · api.openai.com · generativelanguage.googleapis.com …

      standard 28 domains · the default

      strict, plus the package registries and GitHub, so an agent can install and clone.

      registry.npmjs.org · pypi.org · crates.io · proxy.golang.org · github.com …

      open any domain

      standard's files, with the gate open: any domain, still through the proxy, so it's all in the pen's log.

      * · but never localhost or 169.254.169.254

      Or your own

      A profile is a short TOML file. It can extend one of these: lists add up, so you only write what's different.

      To hide one more file from one pen, there's no need for a profile: open the pen's window with prefix+p and use its Files tab.

      Profiles live in fence's config folder, which is hidden from every pen. Only you can move a fence.

      # ~/.config/herdr/plugins/config/fence/profiles/work.toml
extends = "standard"

[files]
write = ["~/.cache/our-tool"]
hide  = ["~/work/other-client"]

[net]
allow = ["npm.internal.example.com",
         "*.internal.example.com:8443"]
      Instructions

      Putting one up

      1. Install the plugin

        Nothing to build. fence has no dependencies.

        herdr plugin install zenodea/fence
      2. Bind the pen's window

        In ~/.config/herdr/config.toml.

        [[keys.command]] key = "prefix+p" type = "plugin_action" command = "fence.open"
      3. Make a pen

        In a project, press prefix+p then n for a new space where every shell is fenced, or f to fence the space you're in. Then start your agent as usual.

      Needs herdr 0.9+ and Node 22.18+; on Linux, bubblewrap. Profiles, commands and the fine print are in the README.
