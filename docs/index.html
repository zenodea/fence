// gates

      
Stopped, then let through.

      

        
When the fence stops something, herdr shows a toast. prefix+p opens the pen's window, where the latest is already at the top. Let it through and it works at once, in every pane of the pen, without restarting a thing.

        
Nothing inside a pen can open a gate: fence's own settings are hidden from it. Only you can.

// how

      
The kernel holds the fence.

      

        
Each pane in a pen runs fence shell. It starts the pen's proxy and herdr gate, then runs your login shell inside the operating system's own sandbox and stays next to it. Your aliases and prompt come along; the agent inherits the fence and can't take it down.

        
If the sandbox can't start, the pane says so and stays empty. It never falls back to an unfenced shell.

      

      
    
        
  • filesEverything read-only but the pen's folder and the agents' own state. Secrets can't be read at all.
    • 
        
  • networkOnly fence's proxy, which only lets the pen's domains through. Going around it fails in the kernel.
    • 
        
  • herdrA stand-in socket: status reports for the pen's own pane, nothing else.
    • 
      

    

    

      

        
        
        
      

      

        
fence policy --sandbox · Seatbelt


; what sandbox-exec enforces for a pen (trimmed)
(version 1)
(allow default)

; writes: only the pen's folders
(deny file-write* (with message "fence:3f9c21aa:w4_p1;")
  (require-not (require-any
    (subpath "/Users/you/work/api")
    (subpath "/Users/you/.claude")
    (subpath "/private/tmp") …)))

; read-only even inside them: things that run later, outside
(deny file-write* …
  (subpath "/Users/you/work/api/.git/hooks")
  (regex #"^/Users/you/\.claude/settings[^/]*\.json") …)

; hidden: secrets, herdr's socket, fence itself
(deny file-read* file-write* …
  (subpath "/Users/you/.ssh") (subpath "/Users/you/.aws")
  (subpath "/Users/you/.config/herdr") …)

; network: fence's proxy and the herdr gate, nothing else
(deny network-outbound …
  (require-not (require-any
    (remote ip "localhost:52114")
    (remote unix-socket (path-literal "/private/tmp/fence-501/g812.sock")))))

(deny appleevent-send …)        ; no osascript → Terminal
(deny mach-lookup … launchservicesd)  ; no `open`
(deny mach-lookup … pasteboard.1)      ; no clipboard


# what bubblewrap runs for a pen (trimmed)
bwrap --die-with-parent \
  --unshare-net --unshare-pid --unshare-ipc --unshare-uts \
  --ro-bind / /                     # the whole system, read-only
  --dev /dev --proc /proc \
  --tmpfs /tmp --tmpfs /run         # no ssh-agent, X11, D-Bus or Docker sockets
  --bind /home/you/work/api /home/you/work/api \
  --bind /home/you/.claude /home/you/.claude \
  --ro-bind /home/you/work/api/.git/hooks … \
  --tmpfs /home/you/.ssh \          # secrets covered over
  --tmpfs /home/you/.config/herdr \
  --ro-bind /dev/null /home/you/.netrc \
  --bind $XDG_RUNTIME_DIR/fence-1000/p812.sock /run/fence/proxy.sock \
  --bind $XDG_RUNTIME_DIR/fence-1000/g812.sock /run/fence/herdr.sock \
  -- node -e "$bridge" 3128 /run/fence/proxy.sock -- $SHELL -l

# no network namespace at all: the bridge forwards one localhost
# port to the proxy outside, and that's the only way out
HTTPS_PROXY=http://127.0.0.1:3128
HERDR_SOCKET_PATH=/run/fence/herdr.sock

      

    

  







  

    
// profiles

    
Three fences, or your own.

    
Every pen has a profile. Switch it from the pen's window; write your own in TOML and it can extend one of these.

    

      

        
strict 13 domains

        
The pen's folder and the agents' own state. Out to the model APIs, and nowhere else.

        

        
api.anthropic.com · api.openai.com · generativelanguage.googleapis.com · …

      

      

        
standard 28 domains · default

        
strict, plus the package registries and GitHub, so an agent can install and clone.

        

        
registry.npmjs.org · pypi.org · crates.io · proxy.golang.org · github.com · …

      

      

        
open any domain

        
standard's files, any domain. Still through the proxy, so every connection is in the pen's log.

        

        
* · but never localhost or 169.254.169.254

      

    

    

      
~/.config/herdr/plugins/config/fence/profiles/work.toml


description = "standard, plus our registry"
extends = "standard"

[files]
write = ["~/.cache/our-tool"]
hide  = ["~/work/other-client"]

[net]
allow = ["npm.internal.example.com", "*.internal.example.com:8443"]

    

  







  

    
// honestly

    
One fence, not a vault.

    
fence is defence in depth: one more thing between a confused or prompt-injected agent and the rest of your machine. So it isn't trusted for more than it is, here's what it doesn't stop.

    

      
Allowed domains can carry data out
The proxy sees the name, not what's inside the TLS. With GitHub let through, an agent can push or make a gist. strict keeps the list to the model APIs.

      
The pen's folder is the agent's
A .env in the project can be read. Keep what the agent shouldn't see outside the pen, or hide it in the profile.

      
Some agent config has to stay writable
Claude Code writes ~/.claude.json, where MCP servers live. fence can't stop a change there, so a tripwire tells you the moment one happens.

      
The keychain stays reachable on macOS
Your agent keeps its login there. macOS still asks you before handing out anything else, and fence stops git asking it for your GitHub credentials.
