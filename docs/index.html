// the pen

A space, fenced. Not the whole machine.

Make a herdr space a pen and every pane in it is fenced as it opens: your login shell, your aliases, your agent, all inside a sandbox the kernel enforces. What the agent starts is fenced too, and it can't take the fence down.

Run it with the permission prompts turned off if you like. If it reaches for your SSH keys, a git hook or a paste site, it meets the fence instead.

🐑 fence-test · standard

      

    

  

  

    

      
Files
The pen's folder, /tmp and the agents' own state are writable. Everything else is read-only.

      
Secrets
~/.ssh, ~/.aws, ~/.config/gh, shell history and browser profiles can't even be read. Tokens are dropped from the environment.

      
Later, outside
.git/hooks, .git/config, .claude/settings.json, .envrc: anything that runs code outside the pen later stays read-only.

      
Network
Only through fence's proxy, only to the domains on the list. Going around it fails in the kernel. localhost is never reachable.

      
herdr
A pen can't open an unfenced pane, type into another one or read it. It can still tell herdr it's working, blocked or done.

      
Other apps
On macOS: no osascript telling Terminal what to run, no open, no clipboard (it often holds a password you just copied).

// gates

      
Stopped at the fence. Let through in a keypress.

      

        
When something is stopped, herdr shows a toast. Press prefix+p and the pen's window lists what was stopped lately. Let a domain through and it works at once, in every pane of that pen, without restarting anything.

        
Nothing inside a pen can open a gate. fence's own settings are hidden from it, so only you can.

// how

    
Kernel-enforced, on both sides.

    

      
Each pane in a pen runs fence shell: it starts the pen's proxy and herdr gate, then runs your shell inside the platform's sandbox and stays next to it. If the sandbox can't start, the pane says so and stays empty. It never falls back to an unfenced shell.

    

    

      

        
macOS

        
Seatbelt · sandbox-exec

        

          
files
A generated profile: writes denied outside the pen's folders, hidden ones denied outright.

          
network
Only the proxy's localhost port and the herdr gate's socket can be reached.

          
denials
The kernel logs each one with the pen's tag; fence follows the log and toasts you.

        

      

      

        
Linux

        
bubblewrap · namespaces

        

          
files
/ read-only, the pen's folders bound back in, secrets covered, a private /tmp and /run.

          
network
No network namespace at all; a tiny bridge forwards one port to the proxy's unix socket.

          
denials
The proxy and the gate report theirs; file writes just fail.

        

      

    

  







  

    
// honestly

    
One fence, not a vault.

    
fence is defence in depth: one more thing between a confused or prompt-injected agent and the rest of your machine. Here's what it doesn't stop.

    
    
      
  • Allowed domains can carry data out. The proxy sees the domain, not what's inside the TLS. With GitHub allowed, an agent can push or make a gist. strict allows only the model APIs.
    • 
      
  • The pen's folder is the agent's. A .env in the project can be read.
    • 
      
  • Agent config that has to stay writable. Claude Code writes ~/.claude.json, where MCP servers live. fence can't stop a change there, so a tripwire tells you the moment one happens.
    • 
      
  • The keychain stays reachable on macOS. Your agent keeps its login there. macOS still asks you before it hands out anything else.
    • 
    

  







  

    

      
Setup.

      
    
        
  1. Install the herdr pluginNothing to build: fence has no dependencies.
          
    herdr plugin install zenodea/fence
    2. 
        
  2. Bind the pen windowIn ~/.config/herdr/config.toml.
          
    [[keys.command]]
key = "prefix+p"
type = "plugin_action"
command = "fence.open"
    3. 
        
  3. Make a penPress prefix+p in a project and hit n for a new pen, or f to fence the space you're in.
    4. 
      

      
Needs herdr 0.9+ and Node 22.18+. On Linux, bubblewrap. Profiles, commands and the details are in the README.
